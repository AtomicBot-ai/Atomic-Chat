# 2026-11-01 — Run the Audios studio on the core's audio.cpp and conf's audio catalog

- **Context:** The Audios page laid out on 2026-10-27 had candidate models, no download and Generate off. The core now has `/atomic/v1/audio/*` and the engine build `audio-cpp` (core ADR 2026-10-29, core PR #61, unreleased), and conf has `models/audio.json` (conf PR #44): Qwen3-TTS 1.7B and MOSS-TTS-Nano for speech, ACE-Step 1.5 Turbo for music, Stable Audio 3 Small SFX for effects, all measured on the real engine. The pinned core is 0.20.5, which has no audio: 404 on `/audio/*` and a refusal for `audio-cpp` on `/engine-builds`.
- **Decision:** `services/audio/` mirrors the core's contract field for field and is the only way to the routes. `services/audio-catalog-registry.ts` reads conf's catalog (remote, cache, bundled baseline, schema_version 1, 1 h TTL, `VITE_AUDIO_CATALOG_URL`), strictly, like the embedding catalog. What a model takes is its `controls`, `defaults` and `ranges`, never its id: a field a model does not list is neither shown nor sent, because audio.cpp refuses an option the family does not declare. `durationSec` is the exception and always goes out for music and effects: Stable Audio otherwise renders its 120-second default. A model file is fetched by the app, sized and sha256-checked, from the catalog's immutable revision (ADR 2026-10-30) to `<data>/audio/models/<filename>`, through the ordinary downloader, cancel-only like embedding models, and removed through the core's `model-files` route. Generate loads the form's model when it is not the loaded one; the core frees the GPU itself, so the app's diffusion arbiter takes no part. A job has phases and no percentage, so the page names the phase and counts seconds over a bar that never fills. Clips live in the core's gallery and the page reads them back; sample rate and channels are shown as each clip reports them, because they differ by model. A model's `attribution` is shown as the catalog writes it in the picker, under the selected model, on its clips and on the Downloads page.
- **Consequences:** The core-without-audio case is a state, not an error: a 404 on `/audio/status` puts the store in `too-old`, the page shows a notice and nothing that can start, nothing is toasted and no further audio call is made; `audio-cpp` joins the engine lists, and every reader already treats an engine the core does not report as absent, so its row appears only when the core reports it. The studio stays behind `PlatformFeature.AUDIO_GENERATION` (dev builds) until a core with audio is pinned; releases show nothing new, and the audio filter on Downloads and the engine row wait for the same flag. Prototype fields with no engine parameter are gone: pitch and sample rate; loop stays as how the player treats a clip and is never sent; tempo is `bpm` and only ACE-Step lists it, empty lets the model choose. Speed stays implemented for a model that lists it; none does today. `requiresVoiceRef` is answered with a plain refusal, because no catalog model needs a cloned voice and the studio cannot record one. There is no way to export a clip yet: the core has no route, so the viewer offers Show in folder.
