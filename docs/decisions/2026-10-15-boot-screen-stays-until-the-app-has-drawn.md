# 2026-10-15 — Keep the boot screen up until the app has drawn, and let no extension hold startup

- **Context:** The startup screen in `index.html` was a spinning logo that `routes/__root.tsx` removed 200 ms after it mounted, whatever had been drawn by then. `ServiceHubProvider` and `ExtensionProvider` render nothing until every extension has loaded, so the window went blank for as long as that took. `ExtensionManager.load()` and `registerActive()` were bare `Promise.all`s with no timeout, and `ExtensionProvider` had no `catch`. So one extension that threw left the window blank for good, one that never resolved held it there, and one that failed to import kept every other extension from registering. On Windows the window has no native title bar (`decorations: false`), and the app's own Minimize/Close live in `WindowFrame`, inside the part that had not drawn. A stuck start was a black window that could not be moved or closed. The owner hit exactly this after a PC crash (2026-10-14), and the frontend wrote nothing about its own startup to `app.log`, so the log could not say where it stopped. The owner also asked for the logo to stop spinning and for the loading panel to be semi-transparent.
- **Decision:** `public/boot.js` owns the boot screen. It is a classic script loaded before the bundle with no imports, so it keeps working when the bundle does not. It shows a static logo and one status line, updated by the app through `window.__radiumBoot.step()` (`lib/boot.ts`). The screen stays up until `<BootReady />`, rendered inside both providers, reports two animation frames after the layout first paints. It writes every step, its timing, early errors and a 5 s heartbeat to `app.log` through `plugin:log|log`. When nothing moves for 20 s, or an error is followed by no progress for 8 s, it turns into a panel that says where startup stopped, with Keep waiting / Restart Radium / Open the log / Quit. On Windows it draws its own drag strip with Minimize and Close. `ExtensionManager` isolates each extension: `registerActive` uses `allSettled`, and each `onLoad` gets 15 s (`EXTENSION_LOAD_TIMEOUT_MS`). A failure or timeout is recorded (`getLoadFailures()`), startup carries on, and a toast with a Restart button says which part didn't start. The panel is semi-transparent and frosted (`backdrop-filter`) *inside* the window, so the app shows through it as it draws underneath.
- **Consequences:** A start that stalls now always shows where and why, can be closed or restarted, and leaves a trail in `app.log`. The app can come up with an extension missing; code that assumes every extension is registered must keep handling `getByName()` returning `undefined`, as it already must for platform-excluded extensions. Desktop see-through (a transparent Windows window with Mica/Acrylic) was rejected: it brings back the softbuffer panic that kills the process when the window is minimised (2026-07-31). The `windowEffects` listed in `tauri.windows.conf.json` stay inert while `transparent` is `false`.
