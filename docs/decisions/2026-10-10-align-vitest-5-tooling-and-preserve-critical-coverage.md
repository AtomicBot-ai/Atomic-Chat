# 2026-10-10 — Align Vitest 5 tooling and preserve critical coverage

- **Context:** PR #122 upgrades the root, core, and web-app Vitest runners to 5.0.3, while their V8 coverage providers remain on 2.x/3.x and core's test UI remains on 2.x. The older coverage provider imports the removed `vitest/coverage` entry point and stops repository verification before tests execute. Vitest 5 also requires Node.js 22.12 or newer and makes Vite a required peer dependency, which Yarn does not install automatically. The existing workflows select Node.js 20. The root coverage configuration has no explicit source inclusion and uses exclusions written relative to `src`, despite collecting both workspaces from the repository root. KaTeX's renderer resolution also lags the stylesheet dependency by one patch release.
- **Decision:** Keep the requested Vitest 5 upgrade and use exactly 5.0.3 for each existing runner, V8 coverage provider, and test UI dependency in the root/core/web-app workspaces. Declare the existing Vite 8.3.0 version as a development dependency in root and core to satisfy the new peer requirement. Use Node.js 24 in the workflows that install this toolchain and document the supported minimum. Explicitly include all core/web-app TypeScript production sources, including unimported files, in global root coverage and qualify test/setup exclusions relative to the repository root. Keep all existing tests and the coverage floors for nine of the ten critical files. Rebaseline only `SetupBackendStep.tsx` after adding rendered-flow tests: statements 97.27%, branches 81.94%, functions 100%, and lines 99.01%. Its former baseline was statements/lines 3.21%, functions 0%, and branches 100%; the branch percentage represented no exercised functions, not complete behavioral coverage. The new AST report counts 72 branch alternatives, including the unused default of the private `finish` callback (every production call supplies the resolved status). Tests cover actual detection, fallback, watchdog, cancellation, download/retry, hot-swap, and restart flows rather than invoking inaccessible closures or constructing impossible states. Align the `rehype-katex/katex` resolution to the web app's 0.18.3 stylesheet dependency. Exclude TypeScript declaration files, which contain no executable code, from coverage in all three configurations. Keep the separately installed extension workspace on Vitest 3.2.4 and explicitly declare its matching V8 provider in both critical llama.cpp extension workspaces, so they cannot accidentally load the root's Vitest 5 provider. Adapt only the two existing constructor mocks to use callable functions and give the connected-provider component test an explicit catalog boundary instead of racing a live background registry fetch.
- **Consequences:** Coverage, UI, and runner packages use compatible exports. CI and local prerequisites match the supported runtime. Vitest 4/5's AST-based coverage and precise path matching may report different percentages; those differences require behavior tests and an explicit migration record. The single documented setup-backend rebaseline replaces the previous empty branch measurement with a tested baseline; production source inclusion remains complete and the other nine floors remain unchanged. KaTeX rendering and CSS use one release. No production UI or runtime dependency is added.
