# 2026-10-20 — Recover and reuse unfinished model download requests

- **Context:** The UI's downloads, paused flags and resume parameters were memory-only. Rust intentionally retained partial files, but restarting the app lost the request needed to display or resume them. A repeated model request could create another import; the Rust command superseded a matching task id rather than deduplicating by source. MLX Hub downloads bypassed the common model service entirely.
- **Decision:** Persist an allowlisted request journal in the existing webview storage through Zustand. Restore unfinished requests as paused rows, reset speed and reply-gate intent, and fetch current credentials when the user resumes. Coalesce simultaneous imports in the model service before asynchronous metadata/preflight work, using provider storage domain plus the HF repo/revision/weight-file identity. All members of a GGUF shard set share one identity; an MLX repository shares one identity regardless of its first weight file. Reuse an existing request id, reopen the panel and report an active duplicate. Refuse different sources competing for the same destination id. Stop and failure retain recoverable requests; completion removes them. MLX Hub requests now use this service and preserve their companion-file list.
- **Consequences:** Recovery never starts network traffic automatically and cached counters never determine file offsets. HF downloads request the existing Rust resume-validation path even without a journal entry, preserving compatible pre-journal partials when requested again; advisory disk preflight still runs for a first request. A missing `.url` marker may recover its identity from a size-matched, structurally valid segment map; an existing marker remains authoritative. No Rust writer, Range, hash, rename or cleanup behavior changes. Tokens, signed query URLs and reply intent are not journaled. Unavailable/full storage cannot fail a live transfer. This journal is per webview/storage profile: it is not a backend-wide or cross-process uniqueness guarantee, and is supplemented at startup by a read-only scan of legacy GGUF, MLX and PrismML model roots. The scan reconstructs jobs from `.url`/`.tmp`/`.parts` sidecars, calculates segmented progress from received ranges, and shows unresolved or conflicting artifacts as blocked rows rather than guessing a source. Repeat requests wait for this migration. MLX repository file lists are rebuilt at the recorded revision only on explicit Resume. Completed-model journals are retired only after a complete scan finds no partial and an installed manifest exists. Managed/media/engine downloads remain outside its scope. Symbolic revisions such as `main` remain symbolic; this does not add commit pinning or ETag validation. Real Tauri/HTTP restart, cancellation-event ordering and rendered UI still require integration validation before release.

## Verification

`node tests/download-recovery.cjs` runs the actual modified store and model service against an in-memory storage implementation and mocked engine/IPC/telemetry dependencies. It requires the repository's TypeScript, Zustand and React dependencies. Legacy migration tests additionally create temporary model/sidecar fixtures, restore jobs without a journal, check startup/retry ordering and compare all fixture names and hashes before and after. It never opens a user model or invokes a real download. The focused harness is not a replacement for `make verify` or real-browser/Tauri acceptance.

The existing Rust missing-range integration test now runs with and without a URL marker. Rust validation remains pending because Cargo is unavailable in the investigation environment.
