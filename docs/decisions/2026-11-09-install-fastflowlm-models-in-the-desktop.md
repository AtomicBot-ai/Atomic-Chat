# 2026-11-09 — Install FastFlowLM models in the desktop

- **Context:** FastFlowLM is a local-only engine for AMD XDNA2 on Windows 11 and Linux x64. The core owns engine builds, readiness, model checks, sessions and maintenance, but deliberately cannot download model payloads. A completion marker alone does not prove that a previous maintenance operation released its hold.
- **Decision:** Read FLM definitions from the shared `atomic-chat-conf` catalog. Use the published `@atomic-chat/core@0.22.0` browser-safe parser and config builder; keep the engine extension on the existing `@janhq/core` runtime contract. Vendor the core settings schema for the existing reset-to-default mechanism. Do not create an independent catalog or reproduce FLM config generation in the app.
- **Publication:** The desktop persists the complete immutable file plan before transferring any bytes. The Rust downloader verifies every file's size and SHA-256, including small configs; the Hugging Face token is applied only to HTTPS Hugging Face requests and is never persisted. Build native configs in staging and write `model.yml` last. Acquire the core maintenance hold before replacing or removing a live directory. Retain the previous directory until core validation and acknowledged maintenance completion; replay the same request ID after a lost response. Startup recovers persisted mutations and restores interrupted transfers as paused downloads.
- **Preparation:** Provider registration, readiness and compatibility come from core. Driver commands and links are display-only. Memory-limit preparation uses explicit consent to the core plan digest and revision, then the trusted bundled CLI with FLM's separate request/receipt protocol. Persist the launch binding by operation and step; recover its original receipt rather than relaunching an unknown helper. NPU residency is separate from GPU chat-model residency.
- **Alternatives:** Implementing FLM config serialization in the app would duplicate the protocol and drift from core. Letting the core download models would violate ownership and bypass the desktop's transfer controls. Replacing live files before confirmed unload could overwrite files that a running model is using. Treating a promoted marker as complete would hide an unresolved maintenance hold.
- **Consequences:** The installer has its own small journals under the existing data folder's `fastflowlm/transfers` and `fastflowlm/host-steps`. Unfinished plans retain their original sources after catalog updates. Core structural checks remain read-only and do not hash multi-gigabyte payloads while listing models. The extension is bundled for Windows/Linux and hidden when core has no provider; it is excluded from macOS packaging. No existing legacy package is renamed.
- **Validation limits:** Targeted fixtures and Chromium geometry checks do not qualify actual Windows/Linux NPU execution, UAC/pkexec, reboot recovery or platform packaging. Those desktop hardware checks remain open. Aggregate verification requires the operator's separate approval and was not run.
