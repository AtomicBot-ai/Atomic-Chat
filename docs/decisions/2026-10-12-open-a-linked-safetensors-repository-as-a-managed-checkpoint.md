# 2026-10-12 — Open a linked safetensors repository as a managed checkpoint

- **Context:** `atomic-chat://models/huggingface/<owner>/<repo>` names a repository and no format (`web-app/src/services/deeplink/parse.ts`), and the Hub opens on GGUF on every launch. A repository the catalog does not carry is resolved from Hugging Face by `convertHfRepoToCatalogModel`, which knows GGUF files and the MLX tag. A model became a managed engine's checkpoint (`is_managed`) only under a managed format: the descriptor's curated list, the safetensors feed, or an `owner/repo` typed into the search (2026-10-03, "Choose TensorRT-LLM models in the Model Hub, as its third format"). So a link to a safetensors repository — `nvidia/Gemma-4-31B-IT-NVFP4`, a curated model of both engines — opened a card with no download section: `DownloadOptionsSelect` renders nothing for a model that is not managed, not MLX and has no quants. The link is the one Hugging Face's "Use this model" menu opens (`local-apps.ts` in `huggingface.js`), offered today on GGUF and MLX pages.
- **Decision:** A repository the Hub resolves for a link, with safetensors weights, no GGUF quant and no MLX tag, is shown as a managed checkpoint wherever at least one managed engine is visible, whatever format the list shows. Its card then asks every visible engine for a verdict, as it does for a repository typed in full under a managed format. Its row and card read as the managed format the Hub shows, else as the first visible engine in registry order (a table row may carry its own `format`). The link, its parser and the Hub's format filter are unchanged.
- **Consequences:** A link to an NVFP4, FP8, AWQ or plain safetensors repository reaches "Download" or "Install" on a machine that has a managed engine. The list keeps the format it had, so the card may show a model the list does not carry. Where no managed engine is visible — macOS, a machine without NVIDIA — the card is as before, with nothing to download; saying why there is left to a later change. Whether the model runs stays each engine's verdict: the Hub reads no quantization and no architecture for a linked repository.
