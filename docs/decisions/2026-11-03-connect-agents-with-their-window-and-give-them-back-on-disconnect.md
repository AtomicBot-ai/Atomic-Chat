# 2026-11-03 — Connect agents with their window, launch-only environment, and give them back on Disconnect

- **Context:** A cross-platform audit of the 20 agent integrations and 3 editors (`integrations-audit-2026-11-03.md`, outside the repo) found that no writer told an agent the served window, so every agent overflowed a 16K–64K local model; that Connect took over user-wide state — Claude Code's global `settings.json`, `setx`/shell-rc variables for Goose, OpenHands, Copilot, Poolside and Muse (Goose overwrote the user's `OPENAI_API_KEY`) — while Disconnect undid only Codex; that the env-only agents started without their variables on Windows and Linux; and a set of platform faults: the user PATH rewritten through PowerShell's OEM output (Cyrillic paths corrupted), npm `.ps1` shims blocked by the default execution policy, npm 12 skipping the postinstall step agents need, Zed's config written outside `%APPDATA%\Zed`, Hermes routed to OpenRouter by a first-match YAML patch.
- **Decision:** `writeAgentConfig` passes the served window (`servedContextLength()`, from the engine's `/props`) to every `configure_*`, which writes it and an output cap of `min(8192, ctx/4)` in the agent's own setting, or nothing when unknown; Connect grows the served model to the agent's `minContextLength` (Hermes 65536, other terminal agents 32768) or stops with the reason. Writers keep the agent's own config files but never user-wide environment: Goose, OpenHands, Copilot (via its `providers.json` entry and `--model`), Poolside and Muse get their variables on the launched process only, and Connect removes only the exact blocks and variables older releases wrote. Every writer records what it replaces in `<config>.atomic-chat-backup.json`; `disconnect_agent` restores those values while they are still ours and removes our entries. Platform fixes: the Windows user PATH is edited through the registry with its type kept; PowerShell launches pass `-ExecutionPolicy Bypass`; `cmd /K` gets a raw, `^`-escaped line, a title and the home directory; npm installs pass `--allow-scripts` on npm ≥ 11.16 and Claude Code prefers its native installer; agents found only in WSL are not connected; per-agent detection looks in the per-user bin directories; Zed uses its per-OS config dir. OpenCode-family models are marked `reasoning` with interleaved `reasoning_content`, Kilo starts with `--model`, OpenClaw joins a running Gateway with `tui`, Atomic Agent gets `appendLocal: false`, dsh is written into its profile patch.
- **Consequences:** A plain `claude`, `goose` or `copilot` started outside Atomic Chat keeps the user's own setup after Disconnect, and env-only agents only use the local server when launched from Atomic Chat. The window written into a config goes stale if the model is reloaded at another size until the next Connect or served-model change. The key of a keyed server reaches some agents on their launch command line (Codex, Poolside, Muse, OpenHands); on macOS it travels in a self-deleting launcher script, not the shell history. Three sidecar implementations exist in core (`backup.ts`, `json-backup.ts`, `json-key-backup.ts`) with the same file name and should be merged. Windows code is type-checked only; real Windows, Linux terminal and per-agent live runs are still to do.
